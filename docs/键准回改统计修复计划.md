# 键准 / 回改统计修复计划

## 目标

先解决“明明有回改/错字，但界面记录为 0”的记录问题，再把键准从当前简化公式升级为“老版思想的新版 WPF/TSF 适配公式”。

本轮优先修复：

- 真实回改 `Hg` 记录不准
- 键准因此恒 `100%`
- 日志统一到 `newgdq.log`
- 最终键准采用老版思想：区分真实回改、拼回、回改前浪费键
- 不改速度、击键、码长、错一罚五等核心统计

### 2. 日志结论

日志证明：

```text
真实回改发生了，但 Hg 没有增加。
```

关键日志：

```text
[BACK] ime lenBefore=6 rawAfter=6 Hg=0 Enter=1 Last=6
[TEXT] back-range len=5 last=6 rawLen=5 realLen=5 Hg=0 Enter=1
```

解释：

- `TEXT back-range` 已经证明 committed 文本从 `6` 缩到 `5`
- 这是实际删除了上屏字
- 但 `BACK` 的 Dispatcher 回调先读到了旧长度 `rawAfter=6`
- 于是误判成“拼音候选框退格”
- 结果 `Enter++`，`Hg` 没有增加

根因：

```text
KeyHook + Dispatcher.BeginInvoke 里读 TextBox 长度存在时序竞争，不可靠。
```

## 老版键准公式

老版 `D:\zrm\tygdq` 里的公式：

```csharp
Low = Glob.TextJs - Math.Abs(Glob.TextBg - Glob.TextHg) * 2 - Glob.TextMcc;
键准 = Low * 100 / Glob.TextJs;
```

变量含义：

```text
TextJs：总键数
TextBg：低层钩子统计到的退格总数
TextHg：真实回改次数
TextBg - TextHg：拼音候选框退格 / 拼回
TextMcc：回改前浪费掉的键数
```

老版重点：

```text
它不是简单 Hg * 2。
它重罚的是“拼回”和“回改前浪费键”。
```

## 新版当前问题

新版当前键准公式：

```csharp
acc = (Keys - Hg * 2) * 100.0 / Keys;
```

问题：

```text
1. Hg 记录本身不准
2. 真实回改目前可能被记到 Enter，而不是 Hg
3. 拼回 Enter 暂时不参与键准
4. 没有 TextMcc 等价字段
```

因此不能直接套公式，必须先把记录修准，再迁移到老版思想的新公式。

## 最终目标：老版思想的新版适配公式

最终不保留当前简化版：

```csharp
acc = (Keys - Hg * 2) * 100.0 / Keys;
```

目标改成更接近老版思想的适配公式：

```csharp
effectiveKeys = Keys - ImeBackspace * 2 - WasteKeysBeforeBackspace;
acc = effectiveKeys * 100.0 / Keys;
```

其中：

```text
Keys：总键数，沿用现有并击/串行双口径
ImeBackspace：拼回，即输入法候选/合成中退格删拼音
WasteKeysBeforeBackspace：真实回改前已经浪费掉的键数，对应老版 TextMcc 思想
```

这个公式吸收老版的核心：

```text
1. 拼回要扣，而且按老版思想扣 2
2. 真实回改不应只粗暴按 Hg * 2 计算
3. 更应该扣掉回改前已经打出去、后来被删除的浪费键
```

但不机械照搬老版字段，因为新版是 WPF + TSF：

```text
1. IME 合成串会实时写进 TextBox.Text
2. 一组拼音可能一次提交多个字
3. 同长度替换、候选选择、合成取消的时序比 WinForms 老版复杂
```

所以实现必须分阶段验证，不能一步把 `TextMcc` 硬搬过来。

## v2 修复方案：先修记录链路

### 原则

```text
真实回改由 TextChanged 记录。
拼回由退格待决标记辅助判断。
不要在 KeyHook 的 Dispatcher 回调里赌 TextBox 更新时间。
```

---

## 第一阶段：修准 Hg 记录，保持公式不动用于对照

### 改动 1：删除 KeyHook 中 racy 的 BeginInvoke 判长逻辑

当前位置大概在：

```text
MainWindow.xaml.cs
KeyHook_KeyDown
Backspace 分支
```

当前逻辑：

```csharp
Dispatcher.BeginInvoke(new Action(() =>
{
    int lenAfter = TbxInput.Text?.Length ?? 0;
    if (lenAfter < lenBefore)
    {
        _session.Hg++;
    }
    else
    {
        _session.Enter++;
    }
}));
```

问题：

```text
BeginInvoke 可能早于 WPF 文本更新执行。
读到旧长度，导致真实回改被误判为拼回。
```

处理：

```text
删除这段对 Hg 的判断。
KeyHook 不再负责真实回改 Hg++。
```

---

### 改动 2：在 TextChanged 的 back-range 分支中记录 Hg

当前位置：

```text
MainWindow.xaml.cs
TbxInput_TextChanged
back-range 分支
```

现有逻辑：

```csharp
if (_session.Started && input.Length < _session.LastInputLen)
{
    hgFrom = input.Length;
    hgTo   = _session.LastInputLen;
}
```

修改为：

```csharp
if (_session.Started && input.Length < _session.LastInputLen)
{
    hgFrom = input.Length;
    hgTo   = _session.LastInputLen;

    _session.Hg++;
    TxtHg.Text = _session.Hg.ToString();

    App.Diag("TEXT",
        $"hg++ len={input.Length} last={_session.LastInputLen} " +
        $"rawLen={rawInput.Length} realLen={realLen} Hg={_session.Hg}");
}
```

理由：

```text
TextChanged 已经发生，文本已更新。
input 是剥离 IME 合成串后的 committed 文本。
这里检测到 input.Length 下降，才是真实回改。
```

---

### 改动 3：键准公式第一阶段暂时不动

保持：

```csharp
acc = (Keys - Hg * 2) * 100.0 / Keys;
```

理由：

```text
先验证 Hg 是否记录准确。
避免同时修改公式导致无法判断问题来源。

注意：这不是最终公式，只是第一阶段的对照策略。
```

## 第二阶段：修拼回记录，并整理 Enter 命名

### 问题

拼回目前也依赖 `BeginInvoke` 判长，不可靠。

### 建议

新增一个退格待决标记：

```csharp
private int _pendingBackspace;
```

按下 Backspace 时：

```csharp
_pendingBackspace++;
App.Diag("BACK", $"pending++ pending={_pendingBackspace} Last={_session.LastInputLen}");
```

在 `TextChanged` 中：

```text
如果本次 input.Length < LastInputLen：
    说明这次退格造成真实回改
    Hg++
    pending 消耗 1

如果发生 TextChanged 但 input.Length 没变：
    可能是删拼音 / IME 合成变化
    不记 Hg
```

拼回当前记在 `_session.Enter`，但这个名字不准确。WPF 里真正的回车键是 `Key.Enter` / `vk == 0x0D`，而这里的 `_session.Enter` 实际语义是：

```text
输入法候选/合成中退格删拼音，也就是“拼回”
```

建议新增或重命名字段：

```csharp
public int ImeBackspace;
```

拼回计数只在明确满足：

```text
有 pending backspace
TextChanged 后 committed input.Length 没有下降
```

时记录。

目标：

```text
真实回改 → Hg++
删拼音 / 候选框退格 → ImeBackspace++
二者不能混记
```

## 第三阶段：落地老版思想的新版适配公式

### 过渡公式：低风险近似老版

公式：

```csharp
low = Keys - ImeBackspace * 2 - Hg;
acc = low * 100.0 / Keys;
```

含义：

```text
拼回扣 2
真实回改先扣 1
暂不实现 TextMcc
```

优点：

```text
简单
风险低
比当前 Hg*2 更接近老版精神
可以作为完整 `WasteKeysBeforeBackspace` 上线前的过渡版本
```

缺点：

```text
不完整复刻老版 TextMcc
真实回改前浪费的键数没有精确扣除
```

---

### 最终公式：新版 WasteKeysBeforeBackspace

新增字段：

```csharp
public int ImeBackspace;
public int WasteKeysBeforeBackspace;
public int KeysSinceLastCommit;
```

或者类似命名：

```csharp
public int TextMccEquivalent;
```

目标公式：

```csharp
low = Keys - ImeBackspace * 2 - WasteKeysBeforeBackspace;
acc = low * 100.0 / Keys;
```

难点：

```text
新版 WPF + TSF 输入法里，一组拼音可能一次提交多个字。
需要正确归属“这次提交耗费了多少键”。

核心思路：

```text
1. 正向 committed 输入时，记录本次提交前消耗的键数
2. 真实回改发生时，把对应的浪费键计入 WasteKeysBeforeBackspace
3. 一次提交多个字时，先按提交事件归属，不强行拆到单字
4. 后续如需更细，再根据 TypeDate / Report 做进一步分摊
```
```

风险：

```text
容易误扣
容易影响码长/击键理解
需要更多日志验证
```

建议：

```text
不要第一步做完整复刻。
但最终方向明确为老版思想的新版适配公式，而不是长期保留 `Hg * 2` 简化版。
```

## 推荐执行顺序

```text
1. 保留统一 newgdq.log
2. 实施第一阶段：Hg 迁移到 TextChanged back-range
3. Release 编译
4. 开诊断复现真实回改
5. 确认 Hg 正确
6. 把 `_session.Enter` 语义整理为 `ImeBackspace`
7. 先上过渡公式：`Keys - ImeBackspace * 2 - Hg`
8. 最后实现 `WasteKeysBeforeBackspace`，切到最终适配公式
```

## 当前结论

优先级最高的不是马上改公式，而是：

```text
真实回改 Hg 记录位置错了。
```

正确修法：

```text
不要在 KeyHook / Dispatcher 里判断真实回改。
应该在 TextChanged 的 committed 文本缩短处记录 Hg。

最终方向：

```text
键准采用老版思想的新版适配公式：
Keys - ImeBackspace * 2 - WasteKeysBeforeBackspace
```
